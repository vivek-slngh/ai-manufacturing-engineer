Case Study — Optical Fiber Drawing Control

→

→
Fiber Drawing
→
Quality

Fiber drawing is a stochastic process with non-linear, delayed dynamics — hard to control with a fixed analytical model. The fiber extrusion plant itself was modeled directly: using measured production data from the drawing process, a long short-term memory (LSTM) network learned the plant's process dynamics, and black-box system identification modeled the production controllers under real noise and disturbances. Combining both produced a closed-loop simulation of the full extrusion system in MATLAB — a digital twin that can replace the slow, iterative work of manually tuning production controllers, and generalizes to other manufacturing plants with similarly constrained operating domains.

Separately, model-free deep reinforcement learning was used to regulate fiber diameter directly and track dynamically varying reference trajectories, outperforming standard approaches such as open-loop, PI, and quadratic dynamic matrix control. Together, both approaches point to the same underlying idea — learn the plant's dynamics from data, then simulate, control, or tune against it in real time.

A "sensor" doesn't have to be hardware. In a security operations pipeline, an endpoint agent, firewall, or log-forwarding appliance emits telemetry at expected intervals just like a physical sensor emits readings — and it can go silent the same way. Statistical baselining and anomaly detection track volume and uptime for thousands of these feeds per client and vendor, catching failures before they become blind spots. Statistics separate naturally sparse or bursty feeds from genuine failures, and a check against expected reporting periods catches feeds that go silent or degrade quietly. It runs as a multi-stage Snowflake/Python pipeline across a multi-tenant environment, with an MCP-connected agent that engineers can ask directly about a sensor's health or anomalous behavior.
